# AX650 算力卡用户指南

8GB 与 16GB 版本　Linux 主机使用说明　V1.0　2026年9月14日

本指南面向已经完成出厂配置的算力卡用户，说明如何在主机安装 AXCL、部署配套 PAC、检查设备并运行模型。不包含 AXP 烧录、DDR 参数修改或 SDK 固件编译。

主机是插有算力卡的开发板或电脑。除特别说明外，本文命令都在主机的 Linux 终端或 SSH 中执行，不在 Windows PowerShell、编译用虚拟机或算力卡串口中执行。

## 1 使用前先准备好三个文件

- **AXCL 主机安装包**：提供 PCIe 驱动、运行库及管理工具。按卡容量、主机架构和操作系统选择。
- **随卡配套 PAC**：主机经 PCIe 加载的卡端运行系统；必须与卡的8GB或16GB配置配套。
- **模型与应用资料**：运行模型时准备兼容的 .axmodel、应用程序和相应输入数据。

### 官方安装包下载

- [16GB 卡安装包目录](https://huggingface.co/AXERA-TECH/AXCL/tree/main/V3.16.0_16G)
- [8GB 卡安装包目录](https://huggingface.co/AXERA-TECH/AXCL/tree/main/V3.16.0_8G)

以上目录于 2026年9月14日核对。16GB 目录中的 Linux 包标识为 `20260729180218_NO26582`，8GB 目录为 `20260731020156_NO5288`，不要只凭同为 V3.16.0 判断文件完全相同。

| 主机与系统 | 选择的安装包 |
|---|---|
| RK3576、RK3588、树莓派等 ARM64，Ubuntu 或 Debian 系 | aarch64 的 .deb |
| Intel 或 AMD 64位电脑，Ubuntu 或 Debian 系 | x86_64 的 .deb |
| RPM 系发行版或龙芯 LoongArch64 | 按系统与架构选择 .rpm 或 loongarch64 包，参考原厂安装说明 |

本指南的完整命令以 Ubuntu / Debian 系为例；已验证的开发板环境为 DShanPi A1、ARM64、内核 `6.1.115-vendor-rk35xx`。其他平台还需满足其 PCIe 与内核驱动条件。8GB 下载目录另有 Windows 安装器，本文不覆盖 Windows 主机驱动安装。

**本卡的 PAC 以随卡交付版本为准。** 官方安装包可能带有默认 PAC，但下载目录标为 8G / 16G 并不代表它已匹配本卡 HG DDR 的具体配置。没有收到配套 PAC 或无法确定版本时，应向供货方索取，不要自行混用。

## 2 准备主机环境

首次安装建议先完成主机软件与配套 PAC 部署，再关机接入算力卡。这样可以避免安装脚本提前加载默认 PAC。若卡已插入，先正常关机并断电后取下；不要带电插拔 M.2 卡。主机不接卡时仍可完成本节及第3、4节的软件准备。

### 检查系统和架构

```sh
uname -m
uname -r
cat /etc/os-release
dpkg --print-architecture
```

`uname -m` 为 aarch64 时选 aarch64 包，为 x86_64 时选 x86_64 包。安装的是主机架构对应的包，不因算力卡芯片本身是 ARM 就在 x86 主机安装 ARM 包。

### 安装基础依赖

```sh
sudo apt update
sudo apt install -y build-essential patch kmod udev pciutils \
  libssl-dev bc flex bison libelf-dev
gcc --version
make --version
```

这些包提供驱动编译、模块管理、PCIe 查询及常见内核头构建依赖。libssl-dev 同时解决本文所用 vendor headers 包的已知依赖问题。编译工具链应符合主机内核要求；原厂文档要求 GCC 至少 9.4。安装失败时先解决依赖，不要继续安装 AXCL。[原厂 Linux 安装说明](https://axcl-docs.readthedocs.io/zh-cn/latest/doc_guide_setup.html)

### 安装与当前内核严格匹配的 headers

若发行版仓库提供当前版本：

```sh
sudo apt install -y "linux-headers-$(uname -r)"
```

若提示找不到 `6.1.115-vendor-rk35xx` 对应包，应从这块开发板所用系统镜像的提供方取得匹配的 `linux-headers-vendor-rk35xx` 包。不要用任意通用 headers 替代，也不要仅创建 build 软链接来伪造匹配。

把已核实版本的本地 headers 包另存为 `vendor-kernel-headers.deb` 后安装：

```sh
sudo apt install -y ./vendor-kernel-headers.deb
ls -l "/lib/modules/$(uname -r)/build/Makefile"
grep UTS_RELEASE \
  "/lib/modules/$(uname -r)/build/include/generated/utsrelease.h"
```

最后一项应与 `uname -r` 一致。若缺文件、版本不符或 headers 未配置成功，先停止并联系系统镜像提供方。更换或升级主机内核后，需要重新匹配 headers 并安装对应内核的 AXCL 驱动。

## 3 安装 AXCL 主机软件

从第1节链接下载正确文件，上传到主机的 `~/axcl-setup`。下载网页中的文件本体，不要把 HTML 页面当成 deb。文件名中的容量目录和架构都要核对。

```sh
mkdir -p ~/axcl-setup
cd ~/axcl-setup
ls -lh
```

### 设置要安装的文件名

以下为 ARM64 主机示例，按卡容量只选择其中一项。x86 主机请改用下载的 x86_64 文件名。

8GB 卡：

```sh
PKG=axcl_host_aarch64_V3.16.0_20260731020156_NO5288.deb
```

16GB 卡：

```sh
PKG=axcl_host_aarch64_V3.16.0_20260729180218_NO26582.deb
```

### 安装并检查结果

```sh
dpkg-deb -f "./$PKG" Package Version Architecture
sudo apt install -y "./$PKG"
dpkg-query -W -f='${Status} ${Version}\n' axclhost
modinfo -F vermagic axcl_host
```

软件包状态应为 `install ok installed`，模块 vermagic 应包含当前 `uname -r`。有些包元数据的 Architecture 显示 all，仍须按文件名选择主机架构。看到“已经是最新版”不代表此前失败的配置已经成功；以最终状态和错误日志为准。

安装后重连 SSH、重新打开终端，或执行 `source /etc/profile`。本文使用工具绝对路径，避免环境变量尚未生效。

| 安装后的常用位置 | 内容 |
|---|---|
| /usr/bin/axcl/ | axcl-smi、axcl_run_model 等工具 |
| /usr/lib/axcl/ | AXCL 运行库 |
| /usr/include/axcl/ | 开发应用使用的头文件 |
| /lib/firmware/axcl/ax650_card.pac | 驱动加载的默认 PAC 路径 |
| /var/log/axclhost-install.log | 主机驱动安装日志 |

AXCL 包会为主机内核编译并安装模块。普通用户不需要另装 SDK 编译目录里的 `axcl_host.ko`，也不要把卡端 Linux 5.15 的模块复制给主机 Linux 6.1 使用。

如果主机已装好供货方验证的 AXCL 且能正常使用，只部署指定 PAC 时可直接进入第4节。需要升级主机包时先备份配套 PAC、停止业务，再按原厂要求卸载旧包并安装新包，之后重新检查 PAC；不要同时安装两个容量包。

## 4 部署配套 PAC

PAC 是保存在主机磁盘上的卡端运行包，包含启动程序、卡端 Linux 和根文件系统等。驱动加载时读取它并经 PCIe 启动算力卡。它不是 .deb 安装包，不用 apt 安装，也不需要用户手工解包。

把供货方为本卡提供的 PAC 上传到主机 `~/axcl-setup/`，保留原文件，并复制一份命名为 `card-runtime.pac` 以便使用以下命令。确认它与卡的 8GB / 16GB 容量和预置配置匹配。[原厂 PAC 使用说明](https://axcl-docs.readthedocs.io/zh-cn/latest/doc_guide_faq.html)

### 核对并备份

```sh
cd ~/axcl-setup
PAC=./card-runtime.pac
sha256sum "$PAC"
```

将结果与供货方该文件的 SHA256 比较；一致后再执行下方命令。仅计算哈希而没有与可信校验值比较，不能判断拿到的是否为正确版本。

```sh
sudo install -d -m 0755 /lib/firmware/axcl
BACKUP="$HOME/axcl-pac-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$BACKUP"
if [ -f /lib/firmware/axcl/ax650_card.pac ]; then
  sudo cp -a /lib/firmware/axcl/ax650_card.pac "$BACKUP/"
fi
```

### 写入默认加载路径

```sh
sudo install -m 0644 "$PAC" \
  /lib/firmware/axcl/ax650_card.pac.new
sudo cmp "$PAC" /lib/firmware/axcl/ax650_card.pac.new && \
sudo mv -f /lib/firmware/axcl/ax650_card.pac.new \
  /lib/firmware/axcl/ax650_card.pac
sudo sync
sha256sum "$PAC" /lib/firmware/axcl/ax650_card.pac
```

两行 SHA256 必须相同，且执行过程中没有错误。目标文件名必须为小写的 `ax650_card.pac`。把带版本号的文件只放在同一目录，驱动不会自动选择它；放到 Windows 的 F 盘也不会让主机加载。

首次安装：执行 `sudo poweroff`，待主机关机后断电，插好算力卡并固定散热片、接好风扇，再一起上电。已正常运行、只更新配套 PAC：停止应用、确认文件校验通过后执行 `sudo reboot`。

复制 PAC 不会立即改变正在运行的卡端系统，需下次完整启动重新加载。每次重新安装或升级 AXCL 包后都应核对该路径，防止配套 PAC 被包内默认文件覆盖。若供货方明确修改过驱动加载参数，应遵循其路径说明，不要只凭 axcl.json 判断 PAC 位置。

## 5 检查设备并运行模型

### 确认 PCIe 枚举和卡端就绪

主机启动完成后执行：

```sh
lspci -nn | grep -iE 'axera|1f4b:0650'
lsmod | grep -E 'axcl_host|ax_pcie'
sudo /usr/bin/axcl/axcl-smi
```

`lspci` 应看到 Axera 或 `1f4b:0650`，但这一步仅代表 PCIe 能发现设备。axcl-smi 出现 Card 0、温度和 CMM 信息，且没有 init fail / no device connected，才表示卡端已经就绪。本卡可能显示为 AX8850，不应只凭名称判断容量。

| 当前配套卡版本 | CMM 总量参考 | 如何理解 |
|---|---:|---|
| 8GB 卡 | 7040MiB | 一部分物理内存供卡端系统使用 |
| 16GB 卡 | 15232MiB | 以该卡配套 PAC 的内存布局为准 |

CMM 的“已使用”会随模型和服务变化。Memory-Usage 是卡端 Linux 的系统内存，不是整张卡的总 DDR；也不能用主机的 free -h 来判断算力卡容量。axcl-smi 不直接显示 DDR 数据率，正常用户无需调整 DDR 频率。

### 运行一个兼容模型

从应用或模型提供方取得 AX650 / AXCL 兼容的 `.axmodel`。下面的 `model.axmodel` 是你准备的实际文件名，不是安装包自动提供的示例文件。普通 ONNX、PyTorch 或 GGUF 文件不能直接替换到此命令。

```sh
cd ~/axcl-setup
sudo /usr/bin/axcl/axcl_run_model --help
sudo /usr/bin/axcl/axcl_run_model \
  -m ./model.axmodel -r 10
echo $?
```

应正常结束，退出码为0，并显示推理时间等信息。这是模型加载与基本运行检查；未提供业务输入和参考输出时，不能据此认定识别结果或精度正确。实际应用还需按模型要求处理尺寸、通道顺序、量化方式和输出解析。[原厂快速上手](https://axcl-docs.readthedocs.io/zh-cn/latest/doc_guide_quick_start.html)

运行应用前后可再次查看 axcl-smi。命令使用 sudo 是为避免首次验证被设备权限或 `/tmp/axcl` 日志权限阻挡；部署非 root 服务时，应由管理员配置相应权限，不建议给系统目录统一设置777。

安装主机运行包不要求完整 SDK 或交叉编译工具链。需要自己编写应用时，可参考 [AXCL 示例代码](https://github.com/AXERA-TECH/axcl-samples)；CMake、OpenCV 等属于相应示例的开发依赖，不是查看设备的必装软件。

## 6 常见问题

| 现象 | 优先检查与处理 |
|---|---|
| build driver fail 或 dpkg 返回1 | 查看安装日志；重点检查运行内核、匹配 headers、libssl-dev 和编译工具。修复根因后再重新配置 AXCL。 |
| headers 提示缺 libssl-dev | 用 apt 安装 libssl-dev；再用 apt install ./vendor-kernel-headers.deb 处理本地包依赖。dpkg -i 本身不会下载依赖。 |
| command not found | 重连终端或 source /etc/profile；先使用 /usr/bin/axcl/axcl-smi。 |
| lspci 找不到 Axera | 正常关机断电后检查插接、主机 PCIe 功能和供电；保存卡端启动日志给供货方。 |
| lspci 有卡，但 axcl-smi 无设备 | 检查驱动模块、PAC 路径与校验值、容量版本，以及主机内核和卡端启动日志。反复安装同一包通常不能修复卡端启动失败。 |
| invalid module format | 模块与运行内核或架构不匹配；安装正确 headers 后为当前内核重装驱动。 |
| 只看到 _apt 无法访问文件的 N 提示 | 该提示本身不等于驱动编译失败；查看后续 E 错误和 axclhost 最终安装状态。 |
| 重装包后容量或启动异常 | 核对默认 PAC 是否被覆盖，重新部署该卡配套版本。不要混用8GB和16GB PAC。 |
| 程序运行一段时间后超时 | 先停止新增任务，保存日志；检查散热、风扇、供电和主机是否休眠，交供货方分析。 |

修复安装依赖或 headers 根因之后，可检查并完成未配置的软件包：

```sh
sudo tail -n 120 /var/log/axclhost-install.log
sudo apt --fix-broken install
sudo dpkg --configure axclhost
dpkg-query -W -f='${Status} ${Version}\n' axclhost
```

## 7 日常维护和问题反馈

运行期间保持散热片和风扇工作，避免主机自动休眠。关机、重启、升级包或更换 PAC 前先停止推理程序。不要通过改文件名或运行 CPU 调频命令来“设置 DDR 4266”。

### 提交问题时收集这些信息

```sh
OUT="$HOME/axcl-support-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$OUT"
uname -a > "$OUT/kernel.txt"
lspci -nnk > "$OUT/pci.txt"
sudo dmesg > "$OUT/host-dmesg.txt"
sha256sum /lib/firmware/axcl/ax650_card.pac > "$OUT/pac.sha256"
```

先保存以上主机信息。若卡此前能够正常通信，再补充设备状态：

```sh
sudo /usr/bin/axcl/axcl-smi > "$OUT/smi.txt" 2>&1
```

若卡端启动或握手已经失败，不要循环调用 axcl-smi；保存主机日志和算力卡调试串口的上电打印，交供货方分析。

同时说明卡容量、主机型号、所用安装包完整文件名和复现步骤；安装问题再附 `/var/log/axclhost-install.log`。若卡还能通信，可按 `axcl-smi --help` 中的 log 子命令收集卡端日志。
