# 六路推流帧率优化说明

## 修改内容

1. 解码帧保留在 AX8850 设备内存中，取消逐帧读回 RK3576、转换 BGR、再上传 NV12 的流程。
2. 分割、深度模型的缩放、留边和 RGB 转换改用算力卡 IVPS，直接写入模型输入缓冲。
3. 在 RK3576 上生成较小的检测标注、分割颜色图和深度颜色图，上传后在卡端放大、叠加。设备缓冲重复使用。
4. 视频显示与推理分为独立线程；显示源帧率分别为 12、25、30、29.97、23.976、24 FPS。推理取最新解码帧，不积压历史推理任务。
5. 渲染保留最多 4 帧的短队列，吸收解码突发输出；六宫格缩放、拼接和最终 H.264 编码全部在算力卡上执行。
6. 增加 `fps.py`，分别报告解码、真实新画面、推理、编码速率及队列丢帧。

RK3576 仍负责文件读取、RTSP 服务、结果后处理、ByteTrack、计数与小尺寸标注图生成。模型输出张量也仍需通过 PCIe 回传，因此推理帧率低于纯 NPU 单次执行速度。视频与推理异步，运动目标的标注可能有时间滞后。

只重新编译并部署了六路应用。此次未修改 AXP、PAC、内核、AXCL 驱动或模型文件。

## 文件位置

| 文件 | 用途 |
|---|---|
| `src/six_app.cpp` | 优化后的源码 |
| `bin/six_app` | 当前运行的 aarch64 可执行文件 |
| `config.json` | 六路配置，`output_fps` 指总览帧率，`source_fps` 必须匹配输入视频 |

本文同目录 `source/` 与 `bin/` 保存对应副本；二进制依赖当前开发板的 ax-pipeline 构建目录和动态库，不是跨系统独立安装包。
