检查输出与记录结果

完成模型部署后，在该模型页面的“查看部署效果”一节对照图片、文字、音频或向量结果。更换自己的输入时，使用本页方法检查并保存输出。

具体模型的部署步骤和实测展示见模型目录。本页说明各类模型通用的检查方法。

检查本次输出​

  1. 保留输入文件，按模型页运行命令，确认日志中的执行后端为 AXCL。
  2. 检查结果文件的修改时间或本次 API 回复，避免误用仓库自带的旧结果。
  3. 按任务核对内容；程序退出码为 0 只能作为其中一项检查。
任务主要检查内容
检测、分割、姿态框、类别、掩码、关键点与原图的位置；明显误检或漏检
深度估计物体边界和近远层次；相对深度不直接当作距离
OCR、语音转写实际文字与输入内容；错字、漏字和顺序
文本与图片问答回复是否切题、是否遵循要求、有无编造细节
语音合成播放输出，检查读音、停顿、杂音和截断
向量、声纹维度、有限数值、归一化，以及匹配对与不匹配对的相似度关系

理解页面中的状态​

状态含义
本机尚未实测已整理文件或步骤，尚无当前主机与算力卡的运行结果
已运行，效果仍需评估模型已加载并输出结果，内容仍有问题或缺少质量核对
固定样例已核对页面列出的输入与输出已经核对，仍以明确记录的缺陷和范围为准

单张图片或短句检查不能替代完整数据集精度评测。长期稳定性、业务性能目标与并发能力需要单独测试。

比较耗时​

先确认指标的计时范围，再比较数字。

  • AXCL Execute：只计设备执行调用，通常不含显式数据复制和前后处理。
  • Python session.run：按页面说明判断是否包含复制、首次调用和记录工具开销。
  • HTTP 耗时：客户端从请求到完整响应的等待时间，不等于纯 NPU 推理时间。
  • TTFT / token/s：分别表示首 token 等待与生成速率；字符数不能代替 token 数。
  • 语音 RTF：处理时间除以音频时长，需注明是否包含加载、音频前端和整个进程启动。

主机 RSS（进程实际占用的物理内存）与卡端 CMM（供模型和缓冲区使用的内存）分别记录。定时采样的最大 CMM 可能遗漏瞬时峰值；单次停止后内存恢复不代表长时间无泄漏。重复测量步骤见性能测量。

保存自己的结果​

每个模型使用独立目录保存：输入、输出、运行日志、命令、模型版本和环境信息。图像保留原图与结果图，问答保留问题和完整回复，语音保留音频与实际文字。

下载空白记录模板，按实际情况填写；未执行的项目保留“未执行”，不要填入估算性能。已有实测的模型页可展开查看样例环境、耗时和适用范围；配套文件与固定版本见该页参考资料。

需要释放磁盘空间时，先保存上述文件，再按模型文件管理清理不再使用的权重。
