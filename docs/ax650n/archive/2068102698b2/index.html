AX8850 六路 AI 视频推流

开发板：192.168.1.44；程序目录：/home/baiwen/ax-pipeline/six。

六路视频已统一为 1920×1080、H.264、yuv420p，保存在 ~/ax-pipeline/video/1080p/。原始视频保留，预处理保持各自源帧率。

1 查看六宫格​

在电脑上打开 VLC，选择 媒体 → 打开网络串流，输入：

rtsp://192.168.1.44:8554/overview

总览为 1920×1080、3 列 × 2 行。每格显示一路 AI 处理结果。

2 查看单路​

以下地址的前缀均为 rtsp://192.168.1.44:8554。

路数视频模型与显示结果路径
1traffic.mp4原 PCD：人、车、骑行目标；跟踪 ID/pcd
2traffic4.mp4YOLOv8s：道路目标检测/vehicle
3traffic3.mp4Helmet：头盔、头部、电动车、自行车/helmet
4traffic2.mp4YOLO26n-Depth：相对深度热力图/depth
5traffic5.mp4YOLO26n-Seg：实例分割与检测框/seg
6traffic6.mp4YOLOv8s + ByteTrack：车辆跟踪、双向过线计数/count

第三路当前素材以街景、公交车为主，本轮抽样没有检出头盔/头部目标；推理和视频输出正常。识别效果需另用近景骑行素材验证。

第四路亮色表示相对更近，不能作为已校准的米制测距使用。

第六路保留车辆跟踪与计数，不使用车牌 OCR。L→R / R→L 分别表示穿过画面参考线的方向。同一跟踪 ID 只计一次。视频循环时清空跟踪状态，总计数继续累积；重启程序后清零。这段素材是移动视角，结果表示画面过线次数。

3 启动、停止​

本次已启动后台服务。开发板重启后，手动执行：

cd ~/ax-pipeline/six
./start.sh

停止：

cd ~/ax-pipeline/six
./stop.sh

查看日志：

sudo journalctl -u ax-six-rtsp -n 20 -o cat

inferred、decoded、encoded 持续增加，表示对应环节在运行。mux_errors、submit_errors 应保持为 0。

4 保存合并视频​

保存一分钟六宫格 MP4：

cd ~/ax-pipeline/six
./record-overview.sh 60

文件保存在 ~/ax-pipeline/six/recordings/。录像直接保存算力卡输出的 H.264，不进行软件重编码；录制结束后自动完成 MP4 封装。

5 调整输入和计数线​

编辑 ~/ax-pipeline/six/config.json，修改相应路的 input。当前配置使用六个处理后的视频，不会覆盖原视频。

第六路的 line_x: 0.4 表示参考线位于画面宽度的 40%；line_deadband: 0.015 用来减少线附近的小幅抖动重复计数。source_loop_us 用于识别当前本地视频的循环边界；更换视频时须重新计算，RTSP 实时源设为 0。

修改后执行：

cd ~/ax-pipeline/six
./stop.sh
./start.sh

当前性能​

七条输出均为 H.264，显示目标为 10 帧/秒。六路新推理结果的更新速度不同：PCD / Helmet 约 6–7 次/秒，车辆检测 / 跟踪 / 深度约 3–4 次/秒，实例分割约 2 次/秒。

显示端复用最新完成推理的画面，因此 10 帧/秒输出不表示每秒执行 10 次新推理，也不表示保留了源视频的每一帧。六路 25/30 帧/秒全帧推理尚未达到。

视频解码、模型执行、H.264 编码均使用 AX8850；绘图、分割后处理、深度着色、六宫格拼接和部分颜色转换在开发板 CPU 上完成。

本次保存的总览视频约一分钟；详细实测值见验证结果。
