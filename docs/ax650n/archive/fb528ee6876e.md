# 第四路视频与开发板 VLC 本地预览

## 视频替换结果

第四路已从 `traffic2.mp4` 换成 `traffic7.mp4`，使用原有 YOLO26n + ByteTrack 模型。

| 项目 | 内容 |
|---|---|
| 原始视频 | `/home/baiwen/ax-pipeline/video/traffic7.mp4` |
| 原始参数 | H.264，3840×2160，29.97 FPS，约 46 秒 |
| 第四路实际输入 | `/home/baiwen/ax-pipeline/video/1080p/traffic7.mp4` |
| 处理后参数 | H.264，1920×1080，29.97 FPS，1380 帧 |

原始视频保留。转换后的文件用于视频推理，不包含音轨。第四路实测输出约 30 FPS，推理约 10 FPS；推理结果与视频独立更新。

## 在开发板 VLC 中观看

选择 **媒体 → 打开网络串流**。

六宫格：

```text
http://127.0.0.1:8850/overview.ts
```

第四路：

```text
http://127.0.0.1:8850/driving.ts
```

也可在开发板桌面终端执行：

```bash
cd ~/ax-pipeline/six
./preview-local.sh
```

只看第四路：

```bash
./preview-local.sh driving
```

桌面上的 `AX8850-local-preview.m3u` 包含总览和六条单路视频地址，可直接用 VLC 打开。

## 为什么使用 HTTP 地址

这台开发板安装的 VLC 3.0.20 构建参数包含 `--disable-live555`，直接播放标准 RTSP 失败。新增的本地服务将算力卡已编码的 H.264 码流转封装为 MPEG-TS，供现有 VLC 播放，不重新编码。

本地预览服务仅监听 `127.0.0.1:8850`，有播放器连接时才启动转封装；播放器关闭后对应进程退出。VLC 显示画面需要在 RK3576 上解码，可能增加主机 CPU 占用。

其他电脑继续使用原来的局域网 RTSP 地址，例如 `rtsp://192.168.1.44:8554/overview`。这里的 `127.0.0.1` 指开发板自身。

## 启动与停止

重启开发板后：

```bash
cd ~/ax-pipeline/six
./start.sh
./preview-local.sh
```

停止推流及本地预览服务：

```bash
./stop.sh
```

`start.sh` 同时启动六路程序和本地预览服务。`sudo ./fps.py` 可以查看实际帧率。
