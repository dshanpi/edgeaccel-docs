# 检查效果与验收

部署验收包含画面效果、码流解码、持续处理和正常停止。服务启动成功不能替代这些检查。

## 查看任务效果

![六路 AI 视频实测结果](/projects/six-streams-20261008/overview.jpg)

*本次板端实际输出截图，使用默认六路输入。[播放完整实测片段](local-preview.md#查看部署效果)。输入内容和播放时刻不同，目标数量与计数也会变化。*

| 画面 | 检查内容 |
|---|---|
| `pcd` | 有目标经过时显示检测框与类别，框随目标移动 |
| `vehicle` | 车辆被框出，画面与标注持续更新 |
| `seg` | 目标上出现分割区域，区域随画面变化 |
| `driving` | 检测框和跟踪标识更新；遮挡后可能重新分配标识 |
| `depth` | 出现随场景变化的相对深度热力图 |
| `count` | 显示计数线，满足过线条件时计数变化 |
| `overview` | 六格均持续更新，布局与各单路任务一致 |

没有目标时不应要求每一帧都有框。检查跟踪和计数需观察连续片段；画面有标注不等于已经量化模型准确率。

## 检查七路 RTSP 解码

在 RK3576 终端执行。每路读取 30 帧；失败时停止循环并打印对应名称，排除问题后重新执行全部检查。

```bash
for stream in pcd vehicle seg driving depth count overview; do
  echo "Checking $stream"
  if timeout 30s ffmpeg -v error -rtsp_transport tcp \
    -i "rtsp://127.0.0.1:8554/$stream" \
    -map 0:v:0 -frames:v 30 -f null -; then
    echo "PASS $stream"
  else
    echo "FAIL $stream"
    break
  fi
done
```

应有七个 `PASS`，且没有解码错误。再检查本机预览链路：

```bash
timeout 30s ffmpeg -v error \
  -i http://127.0.0.1:8850/overview.ts \
  -map 0:v:0 -frames:v 30 -f null -
```

命令应正常退出。若客户端从非关键帧接入产生起始解码告警，重新连接并检查后续完整帧，持续错误不能按通过处理。

## 检查持续运行与退出

至少观察一个完整统计窗口，保存帧率结果：

```bash
cd ~/ax8850-multistream-demo
python3 tools/fps.py
axcl-smi
```

六路处理计数应持续增加，检查期间错误计数不增长。随后按[停止与重启](../../../usage/services.md)确认服务可正常退出、端口释放并重新启动。若用于持续展示，应另外按实际散热、输入、播放器和运行时长进行稳定性测试。

## 查看本次实测结果

**测试环境：** RK3576，内核 6.1.115-vendor-rk35xx，AX8850 **16GB**，AXCL 3.16.0、固件 3.16.0、OpenCV 4.6。使用本指南固定的仓库提交和默认六路资源，以本机源码构建程序运行。

| 验收项目 | 实际结果 |
|---|---|
| 资源与构建 | 11 个模型、视频资源校验通过；源码构建成功 |
| 七路 RTSP | 每路均识别为 H.264 / 1920×1080，各解码 60 帧，无解码错误 |
| 本机 HTTP 预览 | 总览解码 60 帧，无解码错误 |
| 总览录像 | 请求 20 秒，实际 19.700 秒，591 帧完整解码通过 |
| 持续处理 | 末次统计到 310.6 秒；31 组统计中六路提交、封装、渲染替换与编码丢帧计数均为 0，总览错误与丢帧计数也为 0 |
| 正常停止 | 应用退出记录为 `errors=0` |
| 仓库预编译程序 | 限时运行 60 秒正常退出，六路推理与编码均前进，总览解码 60 帧通过 |
| 停止后重新启动 | 两个服务恢复运行，RTSP 与 HTTP 总览分别解码 30 帧通过 |
| 散热条件 | 风扇持续运行；启动前 42°C，运行采样约 49–56°C |

下表来自本次约 60 秒采样窗口，单位为 FPS。它反映六路同时运行时的处理速度，不是模型独占 NPU 的性能。

| 路数 | 新视频帧率 | AI 推理帧率 | 编码帧率 |
|---|---:|---:|---:|
| pcd | 11.96 | 11.98 | 11.98 |
| vehicle | 25.01 | 9.92 | 25.01 |
| seg | 30.00 | 6.17 | 30.03 |
| driving | 29.93 | 10.13 | 29.93 |
| depth | 24.01 | 10.80 | 24.01 |
| count | 24.08 | 9.68 | 24.08 |

总览编码 **30.00 FPS**，该窗口内六路 Drops 和 Errors 均为 0。设备状态采样显示 CMM 约 **1097 / 15232 MiB**；这是本次采样值，不代表峰值占用，也不能仅据此推断其他容量卡已通过验证。

本次验证覆盖基本部署和输出链路，不包含长期稳定性认证；未量化检测准确率、深度测距误差或计数准确率，未验证开发板桌面 VLC 的人工操作。其他容量或软件版本应在相同散热与输入条件下重新验收。

历史数据可查阅[仓库验证记录](https://github.com/dshanpi/ax8850-multistream-demo/blob/2aa772bbf16b8a904ee6ca57877c0e602208bf49/docs/VALIDATION.md)。
