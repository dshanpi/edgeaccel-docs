按任务和容量选择模型

M.2 算力卡 · 模型选型

让业务输出决定模型，
让实测配置决定部署。

从一组可复现的输入开始，确认效果与资源占用，再扩展到自己的数据和应用。

  1. 01明确输出
  2. 02匹配容量
  3. 03对照效果
  4. 04接入应用

选型的结果应是一套可复现的部署配置：模型与权重版本、运行程序、算力卡容量、输入规格，以及预期输出。仅有模型名称或参数量，还不足以确定运行效果和资源需求。

首次使用算力卡，先完成设备检查和首次推理。已完成环境搭建，可直接从下面选择任务。

区分容易混淆的任务​

业务需要选择依据
统计人数、车辆或指定类别先看目标检测的类别与漏检情况；检测框之外的跟踪、去重与告警由应用实现。
读取标牌内容或表单字段OCR 负责文字识别；字段提取还需版面、规则或后续模型处理。
描述图片、回答画面问题选择图像问答模型，并逐项检查回答是否与图片相符。
语音转写、区分说话人转写与声纹是不同任务；会议应用通常还需要分段与时间对齐。
根据知识库回答问题向量模型负责检索，语言模型负责生成；先分别验证，再测试完整问答链路。

按实际容量规划部署​

容量决定资源预算，模型规模、输入与运行方式共同决定实际占用。8GB 与 16GB 的实测记录分别使用，不能相互替代。

选择实际使用的算力卡

先建立单模型运行基线

从有对应 8GB 实测记录的权重与配置开始，先跑通一组固定输入，再测自己的业务数据。

输入规模
先使用部署页的固定尺寸、短音频或单张图片。
文本长度
从短提示和单轮问答开始，核对模型编译时的上下文规格。
运行方式
先单请求、单模型；记录加载后和推理中的 CMM 占用。
扩展顺序
每次只增加一个变量：输入规模、上下文或并发数，重新测量峰值。

此处切换的是验证顺序，不会筛选上方模型，也不表示容量适配已经通过。以部署页标注的卡容量、权重与输入范围为准。

同时检查三类资源​

资源主要用途部署时检查
卡端 CMM模型、运行时工作区、KV Cache、输入输出与相关媒体缓冲用 axcl-smi 查看基线与运行占用；结合运行程序记录峰值，保留余量。
主机内存分词、音频和图像前后处理、数据搬运、服务进程在 Linux 主机使用 free -h，同时观察进程占用与实际输入规模。
存储空间下载权重、解压文件、编译产物、缓存与输出在模型所在分区使用 df -h，为下载临时文件、解压和结果保留空间。

下载文件大小不等于运行内存。 推理过程中资源占用也会变化；一次空闲查询不能代表峰值。组合应用需分别测量模型同时驻留与分阶段运行的情况。

参数量相近的模型也可能具有不同的内存需求。W4A16、W8A16 等量化标记需要与编译目标、上下文配置及运行程序一起核对，不能只按文件大小选型。

确认可用的部署组合​

进入独立部署页后，按以下顺序确认文件与环境。遇到不匹配的项，先解决兼容性，再开始业务效果测试。

确认项应当匹配的内容
主机与算力卡主机架构、卡型号与容量、驱动、AXCL 和配套固件。
模型版本仓库 revision、实际权重路径、编译目标与工具版本。
运行程序本页使用的 AXCL 入口及其版本；Python 程序确认实际使用 AXCLRTExecutionProvider。
配套文件分词器、配置、字典、视觉或音频编码器、解码器及模型分片成套使用。
输入规格图片尺寸、音频采样率、文本长度、上下文、批大小与视频帧数符合本页配置。

同仓库的不同权重也需要分别确认。名称中出现 AX650、Video 或某种量化标记，不足以证明当前 AXCL 入口已覆盖该用法。

只有 .onnx、.pt 或 .safetensors 等源模型时，先查找配套编译产物；需要自行转换和适配时，进入自定义模型接入。大模型运行程序的公共步骤见AXCL 大模型运行时。

用实测结果决定是否继续​

部署页按“准备 → 下载 → 运行 → 效果展示”组织。先用页面提供的相同输入复现结果，再替换成自己的图片、音频或提示词。

页面状态可以据此判断什么下一步
已有部署步骤有明确的操作入口与配套文件说明。查看是否有对应容量、版本的实测记录。
已运行，效果仍需评估页面所列配置产生了实际输出。检查错误、遗漏、截断与业务指标。
固定样例已核对页面的固定输入与输出已进行相应核对。使用有参考答案的业务样本评估泛化效果。
尚未实测、实测受阻或未通过当前记录不足以证明可用。按页面前提处理，或选择已有合适记录的其他配置。

资料状态与实测状态分别阅读；固定样例通过也不等于完整数据集精度、长期稳定性或全部权重变体通过。最新信息以模型目录和独立部署页为准。

围绕业务结果验收​

类型优先检查的结果
检测、分割、姿态目标类别、位置、边缘或关键点；包含目标和不含目标的输入都要检查。
OCR、语音识别参考文字、漏字与错字、顺序；覆盖业务中的方向、噪声或口音。
文本与图像问答事实与计算是否正确、格式是否符合约定、回复是否完整、画面细节是否一致。
语音合成、图像增强实际播放或对照原图，检查可懂度、伪影、杂音、截断及输出尺寸。
向量检索、深度估计检索结果与参考标签、近远关系或标定数据；分数与颜色需按模型定义解释。

随后测量目标负载下的延迟、吞吐、内存峰值与连续运行情况。样本、问题和判断方式固定后，模型之间的结果才有可比性。

固定配置并接入应用​

保留以下选型记录，作为开发、复测与交付的共同依据：

  • 业务输入与预期输出：实际场景、语言、分辨率或采样率，以及有参考结果的测试样本。
  • 部署组合：模型 revision、权重与配置文件、运行程序版本、AXCL／固件、主机与卡容量。
  • 运行参数与结果：上下文、并发、视频采样等设置，以及输出样例、延迟、资源峰值和未覆盖范围。

确认配置后，按需要进入服务接口、视频处理或应用接入与维护。更换权重、输入规格或运行时后，重新执行相同样本，比较结果再更新部署配置。

查找独立部署文档 →按型号、任务和实测状态筛选具体版本。接入自定义模型 →没有配套权重时，完成转换与主机适配。
