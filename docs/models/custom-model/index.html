模型适配 · 自定义接入

把源模型变成可复现的部署组合

从原框架参考结果开始，完成模型转换、AXCL 执行与主机前后处理，再评估业务效果和资源占用。

适用于目录中没有对应权重，或需要部署自训练模型的场景。先在模型目录查找相同网络与任务的 AXCL 入口；已有配套程序时，优先复用其输入输出处理，再按自己的模型逐项核对。

确定需要完成的适配​

已有材料接下来完成什么
已编译权重与配套 AXCL 程序核对目标、版本和输入规格，直接验证完整样例。
已编译权重，没有主机入口准备前后处理，接入 AXCL 或 Python 程序。
ONNX 等可转换的源模型确认工具支持范围，完成转换与输出对比。
只有训练代码或原框架权重先完成导出与原框架对照，再进入转换流程。

转换环境与运行环境分开准备：Pulsar2 所需环境按对应版本文档配置；AXCL 主机程序在连接算力卡的主机运行。M.2 卡的容量、目标芯片与运行时版本都需要记录。

固定输入输出约定​

在导出或转换前保存以下信息。后续每次换权重、量化或前后处理，都使用同一批参考输入对照。

项目保存内容
来源与版本模型仓库、提交号、许可证、导出框架与版本。
输入张量名称、形状、数据类型、布局、颜色顺序及数值范围。
前处理缩放、补边、裁剪、归一化、采样率或特征提取方式。
输出张量名称、形状、含义、坐标与类别索引、解码规则。
配套文件字典、标签、分词器、配置及需要组合使用的其他模型。
参考结果固定输入、原框架输出和业务标签，包含正常与边界样本。

先在原框架确认导出模型的结果与预期一致。动态尺寸、多输入、特殊算子和图内后处理，按工具实际支持范围处理；同名网络也可能具有不同导出图。

转换并保存编译产物​

依据 Pulsar2 工具链文档选择与目标和模型匹配的流程，分别核对开发环境、模型转换、仿真和部署说明。不要仅按最新文档中的默认目标套用配置。

  1. 匹配工具版本与编译目标。 记录工具镜像或版本、目标芯片、运行时要求及输入规格。
  2. 准备校准数据。 覆盖业务中的尺寸、内容、光照或音频分布，并核对校准前处理。
  3. 执行转换并保留日志。 保存转换配置、量化设置、生成文件与 SHA256，确认没有遗漏依赖产物。
  4. 比较转换前后结果。 使用固定输入，先检查张量，再比较业务输出或指标。

不同网络和工具版本需要不同配置。本页不提供通用转换命令；将 .onnx 改为 .axmodel 后缀不会生成卡端程序。转换完成也不表示 AXCL 主机链路已经验证。

接入主机执行流程​

先完成设备检查。使用 AXCL C/C++ 或 Python 接口实现设备初始化、模型加载、输入准备、执行、输出读取及资源释放。Python 路线需确认实际使用 AXCL 后端。

按“读取固定输入 → 前处理 → 执行模型 → 后处理 → 保存结果”的顺序接入。先使用单模型、单请求，保留中间张量，避免一开始同时引入视频、并发与复杂服务。

任务容易影响结果的配套处理
检测、分割与姿态letterbox、RGB/BGR、布局、坐标还原、NMS、掩码或关键点解码。
OCR 与分类字符表、类别顺序、文本方向、空白符或解码规则。
语音采样率、声道、分段、特征提取与音频重建。
文本与多模态分词器、模板、分片命名、上下文、视觉编码器及运行配置。

只有完整输入输出一致，才继续接入业务。大模型还需确认公共运行时是否支持该模型结构；支持 .axmodel 文件不等于支持任意语言模型。

逐层定位结果差异​

检查层次对比方法通过后继续
原框架与导出图同输入比较张量与业务结果转换与量化。
转换前后在工具支持的对比流程中检查数值或任务指标AXCL 加载与执行。
卡端基本执行检查输入输出规格、执行状态和实际输出完整前后处理。
主机完整应用与参考标签核对，覆盖正样本、负样本和边界输入性能与持续运行。
目标负载记录峰值、延迟、资源释放和重复执行固定交付配置。

先修复最早出现差异的环节。只有量化后偏差时检查校准与精度配置；张量一致但业务结果不同，优先检查后处理；加载失败则先检查目标、版本、文件和容量。

保存可交付配置​

模型包中保留模型文件、配置、配套资源、校验值、主机程序版本、运行命令和一组可复现样例。结果说明写明卡容量、AXCL／固件、输入范围、已完成检查与未覆盖范围。

后续更换任一配套文件，重新运行固定样本。记录方式见输出检查方法，通用术语见常用术语。

使用 AXCL Python 接口 →核对后端并接入输入输出张量。集成业务应用 →在结果正确后增加服务与运行维护。
