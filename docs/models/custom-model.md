# 接入自定义模型

本节适用于模型目录中没有对应权重，或需要使用自训练模型的场景。先确认原厂是否已有相同网络与任务的 AXCL 示例，优先复用经核对的前后处理。

## 准备转换输入

记录原始模型来源与许可证，导出版本、输入名称、形状、数据类型（dtype）、布局、归一化以及输出含义。保留一组固定输入及原框架输出作为参考。

动态尺寸、多输入、特殊算子或后处理包含在模型中的情况，应先按转换工具支持范围处理。模型名称相同不意味着导出图相同。

## 转换为卡端模型

按所选 AX650 目标与运行时版本查阅 [Pulsar2 文档](https://pulsar2-docs.readthedocs.io/zh-cn/latest/)。量化时准备代表真实业务分布的校准数据，保存工具版本、转换配置、日志和生成文件的 SHA256。

不同模型和工具版本需要不同配置，本指南不提供可套用所有网络的转换命令。`.onnx` 改名为 `.axmodel` 不会完成编译。

## 接入主机程序

使用 AXCL C/C++ 或 [Python 接口](../usage/python.md)完成设备初始化、模型加载、输入准备、执行、输出读取与释放。先对照固定输入检查张量，再增加业务后处理。

视觉模型需核对缩放补边（letterbox）、颜色空间、坐标还原和重复框筛选（NMS）；OCR 需核对字符表；语音需核对采样与特征提取；大模型需核对分词器、分层命名、上下文缓存（KV Cache）与配置。术语说明见[常用术语](../reference/glossary.md)。

## 分层验证

1. 原框架与转换后模型使用同一批输入，比较输出或业务指标。
2. 使用 AXCL 工具检查模型基本运行。
3. 使用真实主机应用检查完整前后处理。
4. 检查资源、性能和重复运行，按[模板](../reference/validation.md)记录。

出现精度差异时保留中间结果，先定位量化、前处理或后处理，再调整性能配置。
