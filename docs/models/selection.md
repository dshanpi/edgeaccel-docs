# 按任务和容量选择模型

先确定任务，再选择有 AXCL 入口的程序与配套权重。模型名、参数量或芯片支持列表不足以单独证明它能在 M.2 算力卡上运行。

## 选择部署路径

| 需要完成的任务 | 建议先阅读 | 后续扩展 |
|---|---|---|
| 图片目标检测 | [YOLO11s](deploy/yolo11.md) | YOLO26、行业检测、开放词汇检测 |
| 实例轮廓与人体关键点 | [实例分割](segmentation.md) / [人体姿态](pose.md) | 不同尺寸模型、视频流 |
| 相对深度 | [深度模型](depth.md) | 深度可视化与业务规则 |
| 中文文本对话 | [Qwen3-0.6B](deploy/qwen3-0-6b.md) | Qwen3-1.7B、适配配置明确的量化模型 |
| 图像与短视频问答 | AXCL 运行时支持的较小 VLM | 增加图像数量、采样帧和上下文 |
| 语音交互 | 配套版本的 Whisper AXCL、MeloTTS AXCL | 其他 ASR / TTS，逐项确认 AXCL 后端 |

具体下载入口与适配级别见[模型目录](catalog.mdx)。这些是验证起点，尚未构成当前设备的性能或容量承诺。

## 评估卡端与主机内存

卡端 CMM 同时供模型、KV Cache、输入输出、视频缓冲等使用。主机仍需承担文件读取、分词、部分前后处理和服务进程。下载文件总大小不等于运行内存。

8GB 卡先验证单个小模型、短上下文和单请求。16GB 卡也需要根据空闲 CMM 判断，不能直接推断任意 8B 模型、长视频或多并发一定可运行。历史 Qwen3-VL-8B 的 16GB 记录不能作为 8GB 卡的容量依据。

## 核对兼容性

逐项记录：主机架构、AXCL/PAC、模型提交号、编译目标与工具版本、运行程序提交号、输入尺寸和量化类型。W4A16、W8A16 等表示量化配置，不等于可自动互换的运行文件。

对 `.onnx`、`.pt`、`.safetensors` 等原始模型，先确认是否已有适配权重；没有时走[自定义模型接入](custom-model.md)。不要重命名后缀代替转换。

## 阅读目录中的状态

- **资料状态**说明是否已有可执行步骤、专用脚本或仍需适配。具体含义见[目录说明](catalog.mdx#判断能否开始部署)。
- **实测状态**说明是否运行过、是否核对固定样例。两者分开判断：有部署步骤不等于实测通过。

各模型的最新状态见[模型目录](catalog.mdx)。已实测页面在运行步骤后展示实际结果；“已运行，效果仍需评估”与“固定样例已核对”分别标注。没有实测的页面只说明预期输出，不展示模拟结果。
