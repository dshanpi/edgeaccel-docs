# 按任务和容量选择模型

<SelectionIntro />

选型的结果应是一套**可复现的部署配置**：模型与权重版本、运行程序、算力卡容量、输入规格，以及预期输出。仅有模型名称或参数量，还不足以确定运行效果和资源需求。

首次使用算力卡，先完成[设备检查](../usage/device-check.md)和[首次推理](../usage/first-inference.md)。已完成环境搭建，可直接从下面选择任务。

## 从需要的输出选择入口

先区分最终需要的是框、文字、向量、音频还是生成回复。下面给出常用部署入口；效果状态来自本站现有记录，适用容量与测试范围见对应页面。

<TaskChoices />

需要物体轮廓、人体关节或文本指定目标时，分别进入[分割](segmentation.md)、[姿态](pose.md)与[开放词汇检测](open-vocabulary.md)。其他模型、量化版本与组合应用可在[完整模型目录](catalog.mdx)中查找。

### 区分容易混淆的任务

| 业务需要 | 选择依据 |
| --- | --- |
| 统计人数、车辆或指定类别 | 先看目标检测的类别与漏检情况；检测框之外的跟踪、去重与告警由应用实现。 |
| 读取标牌内容或表单字段 | OCR 负责文字识别；字段提取还需版面、规则或后续模型处理。 |
| 描述图片、回答画面问题 | 选择图像问答模型，并逐项检查回答是否与图片相符。 |
| 语音转写、区分说话人 | 转写与声纹是不同任务；会议应用通常还需要分段与时间对齐。 |
| 根据知识库回答问题 | 向量模型负责检索，语言模型负责生成；先分别验证，再测试完整问答链路。 |

## 按实际容量规划部署

容量决定资源预算，模型规模、输入与运行方式共同决定实际占用。8GB 与 16GB 的实测记录分别使用，不能相互替代。

<CapacityPlanner />

### 同时检查三类资源

| 资源 | 主要用途 | 部署时检查 |
| --- | --- | --- |
| **卡端 CMM** | 模型、运行时工作区、KV Cache、输入输出与相关媒体缓冲 | 用 `axcl-smi` 查看基线与运行占用；结合运行程序记录峰值，保留余量。 |
| **主机内存** | 分词、音频和图像前后处理、数据搬运、服务进程 | 在 Linux 主机使用 `free -h`，同时观察进程占用与实际输入规模。 |
| **存储空间** | 下载权重、解压文件、编译产物、缓存与输出 | 在模型所在分区使用 `df -h`，为下载临时文件、解压和结果保留空间。 |

**下载文件大小不等于运行内存。** 推理过程中资源占用也会变化；一次空闲查询不能代表峰值。组合应用需分别测量模型同时驻留与分阶段运行的情况。

参数量相近的模型也可能具有不同的内存需求。`W4A16`、`W8A16` 等量化标记需要与编译目标、上下文配置及运行程序一起核对，不能只按文件大小选型。

## 确认可用的部署组合

进入独立部署页后，按以下顺序确认文件与环境。遇到不匹配的项，先解决兼容性，再开始业务效果测试。

| 确认项 | 应当匹配的内容 |
| --- | --- |
| 主机与算力卡 | 主机架构、卡型号与容量、驱动、AXCL 和配套固件。 |
| 模型版本 | 仓库 revision、实际权重路径、编译目标与工具版本。 |
| 运行程序 | 本页使用的 AXCL 入口及其版本；Python 程序确认实际使用 `AXCLRTExecutionProvider`。 |
| 配套文件 | 分词器、配置、字典、视觉或音频编码器、解码器及模型分片成套使用。 |
| 输入规格 | 图片尺寸、音频采样率、文本长度、上下文、批大小与视频帧数符合本页配置。 |

同仓库的不同权重也需要分别确认。名称中出现 AX650、Video 或某种量化标记，不足以证明当前 AXCL 入口已覆盖该用法。

只有 `.onnx`、`.pt` 或 `.safetensors` 等源模型时，先查找配套编译产物；需要自行转换和适配时，进入[自定义模型接入](custom-model.md)。大模型运行程序的公共步骤见[AXCL 大模型运行时](llm-runtime.md)。

## 用实测结果决定是否继续

部署页按“准备 → 下载 → 运行 → 效果展示”组织。先用页面提供的相同输入复现结果，再替换成自己的图片、音频或提示词。

| 页面状态 | 可以据此判断什么 | 下一步 |
| --- | --- | --- |
| **已有部署步骤** | 有明确的操作入口与配套文件说明。 | 查看是否有对应容量、版本的实测记录。 |
| **已运行，效果仍需评估** | 页面所列配置产生了实际输出。 | 检查错误、遗漏、截断与业务指标。 |
| **固定样例已核对** | 页面的固定输入与输出已进行相应核对。 | 使用有参考答案的业务样本评估泛化效果。 |
| **尚未实测、实测受阻或未通过** | 当前记录不足以证明可用。 | 按页面前提处理，或选择已有合适记录的其他配置。 |

资料状态与实测状态分别阅读；固定样例通过也不等于完整数据集精度、长期稳定性或全部权重变体通过。最新信息以[模型目录](catalog.mdx)和独立部署页为准。

### 围绕业务结果验收

| 类型 | 优先检查的结果 |
| --- | --- |
| 检测、分割、姿态 | 目标类别、位置、边缘或关键点；包含目标和不含目标的输入都要检查。 |
| OCR、语音识别 | 参考文字、漏字与错字、顺序；覆盖业务中的方向、噪声或口音。 |
| 文本与图像问答 | 事实与计算是否正确、格式是否符合约定、回复是否完整、画面细节是否一致。 |
| 语音合成、图像增强 | 实际播放或对照原图，检查可懂度、伪影、杂音、截断及输出尺寸。 |
| 向量检索、深度估计 | 检索结果与参考标签、近远关系或标定数据；分数与颜色需按模型定义解释。 |

随后测量目标负载下的延迟、吞吐、内存峰值与连续运行情况。样本、问题和判断方式固定后，模型之间的结果才有可比性。

## 固定配置并接入应用

保留以下选型记录，作为开发、复测与交付的共同依据：

- **业务输入与预期输出**：实际场景、语言、分辨率或采样率，以及有参考结果的测试样本。
- **部署组合**：模型 revision、权重与配置文件、运行程序版本、AXCL／固件、主机与卡容量。
- **运行参数与结果**：上下文、并发、视频采样等设置，以及输出样例、延迟、资源峰值和未覆盖范围。

确认配置后，按需要进入[服务接口](../usage/api-service.md)、[视频处理](../usage/video.md)或[应用接入与维护](../usage/application-guide.md)。更换权重、输入规格或运行时后，重新执行相同样本，比较结果再更新部署配置。
