# 测量性能与稳定性

先用实际输入完成正确性检查，再测试速度。固定主机、卡容量、AXCL、PAC、模型版本、输入与参数，避免把不同测试条件混成一组结果。

## 区分指标

| 指标 | 记录方式 | 不应替代 |
|---|---|---|
| 模型推理延迟 | 模型执行阶段耗时，标明是否含数据传输 | 视频整条链路耗时 |
| 图片 / 视频吞吐 | 完整处理的图片或输出帧／时间 | 只用 NPU 延迟倒数估算 |
| 端到端延迟 | 从输入进入到结果可用 | 平均 FPS |
| TTFT | 请求发出至首 token 返回 | 全部文本生成时间 |
| tokens/s | 明确计时区间的输出 token 数／时间 | 中文字数／时间 |
| RTF | 音频处理时间／音频时长 | 首字延迟 |
| 峰值内存 | 主机内存与卡端 CMM 分别记录 | 模型文件大小 |

## 完成短时基准

1. 停止其他占卡应用，记录设备温度和空闲内存。
2. 首次运行保存模型加载时间，再进行预热。
3. 固定输入连续运行，记录次数、平均值及波动；有逐次样本时计算 P50 / P95（延迟的第 50 / 95 百分位数）。
4. 分别报告预处理、推理、后处理与总体时间。

`axcl_run_model` 可用于模型基本基准；真实业务需用对应应用测量。原厂树莓派或其他主机的数据只作背景，不能直接填入 RK3576 结果。

## 完成稳定性检查

建议从单次、10 次重复、30 分钟连续运行逐步扩展，再按产品要求做更长时间测试。这里是验证计划，不是已经完成的时长。

记录温度、CMM、主机内存、错误次数、吞吐变化和退出后资源回收。视频需加入断流与恢复，大模型需加入重置上下文与较长输入。若出现设备掉线、温度异常、内存持续增长或结果错误，停止增加负载并保存日志。

## 调整配置后重测

先定位主机解码、CPU 前处理、PCIe 传输或卡端推理中的主要耗时，再调整线程、队列和拷贝流程。CPU 亲和性、IRQ、频率节点因主机而异，不复制其他平台的固定路径与频率值。

按[验证模板](../reference/validation.md)记录每次变更，保留基线。

依据：[原厂 AXCL 基准说明](https://axcl-docs.readthedocs.io/zh-cn/latest/doc_guide_npu_benchmark.html)、[算力卡使用提示](https://awesome-edge-docs.readthedocs.io/zh-cn/latest/06_samples/samples_axcl.html)。
